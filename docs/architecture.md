# 架构设计

本文说明系统的分层结构、状态图路由、模型判定与规则校验的数据流，以及"模型说什么、程序信什么"的核验机制。数字与能力口径同 [README](../README.md)，不重复展开。

## 分层

| 层 | 位置 | 职责 |
| --- | --- | --- |
| domain | `src/mla/domain` | 纯函数内核：规则判定（rules）、必备条款缺项（missing）、条款候选（clauses）、槽位与追问规则（slots、asking）、可溯源校验（verify）、越界判定（boundary）、清单组装（checklist）、数据模型（models）、策略常量（policy）、字段目录（field_catalog）。零 I/O、零模型依赖，相同输入必然相同输出 |
| ports | `src/mla/ports` | 接口定义：存储（repository）、生成（generation）、检索（retrieval）。只声明协议，不含实现 |
| adapters | `src/mla/adapters` | 接口实现：SQLite 持久化（persist）、正则抽取（extract）、模型抽取（extract_llm）、BM25 / 向量 / 混合检索（rag）、DeepSeek 调用（llm）、Word 与 PDF 解析（files）、凭据文件读写与权限收紧（auth_file）、语义向量（embedding） |
| graph | `src/mla/graph` | LangGraph 状态图：13 个固定节点、状态定义与条件路由 |
| services | `src/mla/services` | 用例编排：账号与权限（auth）、凭据解析（credentials）、运行期引导与迁移（bootstrap）、检索装配（retrieval）、核对任务（tasks）、条款审查（clause_review）、共识层对账（consensus）、追问（asking）、生成式表述与来源校验（drafting）、问答循环（qa_agent）、Word 报告（report） |
| api | `src/mla/api` | HTTP 层：应用工厂与同源校验（app）、依赖注入与会话（deps、sessions）、权限矩阵（permissions）、错误体（errors）、异步任务登记（jobs）、DTO（schemas）、展示口径（presenters）、端点（routes/*） |
| web | `web/` | Vue 3 + Element Plus 单页界面（Vite 构建）：只渲染 API 给的 DTO，不做判定、计数、分级与排序；生产态由 FastAPI 同源托管构建产物 |

依赖方向单向：外层依赖内层，domain 不 import 任何 adapter。节点函数用闭包绑定依赖集合（`Deps` 实例不进 state），单元测试注入假实现即可离线跑全图；节点返回状态增量，不原地修改。

## 界面层：FastAPI + Vue

0.4.0 起界面分两半，界面框架不进内层：`api` 只把 `domain` / `services` / `adapters` 的产物转成 DTO，`web` 只渲染 DTO。

| 位置 | 内容 |
| --- | --- |
| `src/mla/api/app.py` | 应用工厂 `create_app()`（`uvicorn mla.api.app:create_app --factory`）：同源校验中间件（带 `Origin` 时比对 `Host`）、请求号、错误处理器、路由挂载、静态托管与 SPA 回退。默认只绑回环地址、不开 CORS |
| `src/mla/api/deps.py`、`sessions.py`、`permissions.py` | 每请求的仓储与会话解析、内存会话表（30 分钟空闲 / 12 小时绝对过期）、能力矩阵（页面看不到不等于接口能调，授权在服务端） |
| `src/mla/api/jobs.py` | 核对链路的进程内任务登记（单 worker），`POST /checks` 返回 202 + `job_id`；进程重启即失效，已落库历史不受影响 |
| `src/mla/api/schemas.py` | 出入口 DTO（pydantic）；`presenters.py` 是展示口径的唯一位（结论三层拆分、时间与耗时文案、历史筛选与趋势、问答上下文），`web` 不补算 |
| `src/mla/api/routes/` | setup / auth / enterprise / contracts / settings / admin / checks / history / report 九组端点；未知 `/api/*` 一律 JSON 404 |
| `web/src/` | `views/` 页面、`components/`（结果页三层与折叠器）、`api/`（契约客户端与错误归一）、`stores/` 会话、`router/` 守卫；ECharts 只在展开趋势图时按需加载 |
| `web/tests/`、`web/e2e/` | vitest 单测（DTO 渲染、路由守卫）与 Playwright E2E（真实后端进程 + 打桩模型，两个端口验证「有模型 / 无模型」两条路径） |

同源是这条链的前提：开发态 Vite 把 `/api` 代理到 8000 且必须 `changeOrigin: false`，生产态由同一个 FastAPI 进程托管页面，因此不需要 CORS，也不接受跨站写请求。

## 数据与存储

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 账号、企业、合同、任务、日志、设置 | 用户级目录下的 `mla.sqlite3`（`MLA_HOME`，Windows 默认 `%LOCALAPPDATA%\mla\`；SQLite，6 张表：users / enterprises / contracts / tasks / logs / settings） | 运行时数据，不进包目录，也不再绑定启动目录。一个账号绑定一个企业；企业 ID 为空的查询不得返回全库数据；任务删除为软删，日志留痕；`settings` 存通用键值设置（键值对，如界面侧配置项），**不存模型 Key** |
| 法源、规则、触发器、必备条款规格、案例、回归集与留出集 | `src/mla/data/` 下的 JSONL / YAML 文件（随包分发，安装后在 `site-packages/mla/data/`） | 判定依据，只读，经 `mla.config.data_path()` 解析，各有独立校验脚本把关结构一致性 |
| 语义向量缓存 | 用户级目录下的 `index/`（`MLA_HOME`，Windows 默认 `%LOCALAPPDATA%\mla\index\`） | 向量检索路径的本地缓存目录（运行期可写，不写进包目录，不随启动目录分散）；BM25 路径不依赖它 |
| 模型 Key | 用户级 `auth.json`（环境变量 `MLA_LLM_API_KEY` 可临时覆盖）；向量 Key 仍可来自 `DASHSCOPE_API_KEY` 或 `secrets.toml [embedding]` | 明文 JSON + 权限收紧，不进数据库、不进仓库；解析只走 `services.credentials` 一处，来源标签只有环境变量 / 用户凭据文件 / 未配置 |

## 状态图：13 个固定节点

路由写死在图的边上（`graph/build.py`），模型没有任何通道改变图结构或路由条件：

```
START → intake → extract → boundary
  boundary ── 越界 ────────→ refuse → END
           ── 问答模式 ────→ retrieve
           ── 核对模式 ────→ slots_check
  slots_check ── 缺阻断项且未超轮数上限 → ask → slots_check
              ── 事实齐全或已达轮数上限 → retrieve
  retrieve ── 问答模式 → qa_answer → verify
           ── 核对模式 → rule_check → checklist → verify
  verify ── 通过 → output → END
         ── 失败 → degrade → output → END
```

| 节点 | 职责 | 模型参与 |
| --- | --- | --- |
| intake | 入口，补齐状态默认值，防止下游拿到 None | 无 |
| extract | 合同关键字段抽取：正则优先、模型只补缺失字段，用户显式提供的事实优先覆盖；正文超过字数上限截断 | 可选 |
| boundary | 越界判定两层：劳动用工术语定向 → 未命中任何领域词则保守拒答 | 无 |
| slots_check | 阻断项与可补充事实是否齐全，纯代码 | 无 |
| ask | 生成追问并把轮数加一：程序定字段，模型只润色问句，八道核验不过逐条退回固定问句 | 可选 |
| retrieve | 法源检索：BM25 与向量混合（RRF 融合），已做时效过滤；无 Key 或断网回退纯 BM25 | 无 |
| rule_check | 16 条数值校验：规则四态转三态（ok / mismatch / needs_fact，即一致 / 不一致 / 待补事实），只输出校验信号，不单独产出用户可见结论；不一致的校验点在共识层追加一条"确定冲突"条目（数值与法条不一致），校验信号与模型结论在共识层对账 | 无 |
| checklist | 汇总图内风险清单；生成处理建议（必须带依据，无模型则不生成）；旁路执行必备条款缺项检测；最终 `items` 由共识层在服务层覆盖 | 可选 |
| qa_answer | 受限问答：依据检索到的条文作答，无模型或无条文直接拒答 | 是 |
| verify | 可溯源校验：结论与建议的依据集合＝规则表法条与规则 ID ＋ 本轮检索命中 | 无 |
| refuse | 拒答并给转介建议，不产出任何结论 | 无 |
| degrade | 校验失败的降级出口：保留结论，标记"依据不足" | 无 |
| output | 结果落库，写日志（token、耗时） | 无 |

越界判定没有"检索零命中兜底"这一层，原因在图的顺序上：`boundary` 跑在 `retrieve` 之前，此时还没有任何检索结果可看，"检索不到法源"这个条件自己就无从判定。拒答只由 `domain/boundary.py` 的两条纯规则决定——命中越界词直接拒（归因 `terms`），未命中任何领域词也拒（归因 `default`，宁可少答不乱答）；`facts`（只有结构化事实、无自由文本）与 `llm`（问答时模型判为越界）两处归因由节点另行标注。

条款级审查（存在性域）不在图内：图跑完后由 `services/tasks.py` 统一编排——先跑条款审查，再把模型结论与 `rule_check` 的校验信号交给共识层（`services/consensus.py`），由共识层按 `statute_id` 对账后产出最终的 `items`，一起落库。这样图的主干保持确定性，条款审查失败也不影响其余环节跑完。但注意边界：**模型不可用时核对在入口就被拒绝**（服务层抛 `NoModelError`），不再有"条款审查不执行、规则照跑"的半套结果。

## 判定与校验的数据流

### 条款判定：模型主通道（services/clause_review.py）

33 条触发器扫描合同正文，召回可疑条款候选，每个候选带段落号、原文片段与该触发器允许引用的法条闭集。触发器只负责召回：命中只说明"这段值得模型看一眼"，不出等级、不生成结论，也不单独展示。候选分批送模型逐条判定 A/B/C 级，要求给出证据原文、法条引用、法条原文摘抄与影响度建议 → 每条输出过六道程序核验（见下节）→ 通过的结论进共识层。模型在候选之外自提的问题，条数封顶、一律记 C 级，不采信其自报等级。开关 `MLA_CLAUSE_REVIEW` 默认开启；模型调用失败或 JSON 非法时该层输出空结果加错误说明，不阻塞主流程。

### 共识层（services/consensus.py）

模型结论 × 数值校验信号 → 最终条目，位置在条款审查之后、写库之前。对齐判据只有一条：`statute_id` 交集，不看自然语言理由。处置四类：数值不一致而模型说没问题 → 降一级；数值落在法定区间而模型判 A/B → 降一级；数值不一致且模型没有相关结论 → 追加一条 C 级复核项（`source="rule_check"`，程序来源，不是模型结论）；等级只降不升，未知等级按 C 处理。条目上的影响度与确定性（`domain/grading.py`）也在这一步算清：影响度只认合同要素骨架，模型建议不一致时只记诊断。

### 数值校验（rule_check 节点）

抽取与用户输入合并成结构化事实 → 逐条规则先看前提（每条规则可带两组前提，`and` / `or` 决定组合关系）→ 前提适用的进入数值比较 → 节点内部保留四态（违规、合规、不适用、无法判定），再转成三态校验信号 `ok` / `mismatch` / `needs_fact` 随任务落库。"无法判定"再细分两类归因：缺前提字段，或前提已满足但判定字段缺失——两种都显式留痕，绝不折叠成"合规"。校验信号本身不产出用户可见结论，只有共识层追加的复核条目会出现在结果里。

### 缺项检查（checklist 节点旁路，domain/missing.py）

按《劳动合同法》第十七条的九类必备条款规格逐行匹配合同正文，不跨行拼接；每类输出四态之一：已写、缺失、未见、需人工确认。只判"有没有写"，不判合法性——写了"自愿放弃缴纳社保"也算已写，其违法性归条款判定（触发器召回）管。第（九）类为兜底规格，不判、不进覆盖率分母；正文过短时整体落"需人工确认"，不产生缺失结论。结果单独落库，不混入共识层产出的条目列表，避免污染数值校验的评测口径。

## 为什么模型不能决定流程

流程即代码：哪个环节接哪个环节、什么条件拒答、什么条件补问、什么条件降级，全部写在状态图的边和路由函数里。模型的决策空间被压缩到三个点，且每个点都有程序兜底：

1. 问答循环内（services/qa_agent.py）：决定调什么工具、查几轮、何时停。工具只暴露"查法条 / 查规则"两个；工具失败或轮数用完，回退固定检索作答；收敛后的回答仍只接受工具已返回的来源。
2. 追问环节：从程序给定的字段闭集里挑可补充项、把问句润色得更自然。问什么、最多问几条、阻断项必须全覆盖，由程序决定。
3. 条款判定与影响度建议：对触发器召回的候选给 A/B/C 等级、证据原文、法条引用、法条原文摘抄与影响度建议。引用不得越出候选闭集，摘抄必须与法条原文逐字一致，等级与摘抄都要过核验；影响度以合同要素骨架为准，模型建议越域或与要素不一致时只记诊断、不改变展示。

这样做的收益是错误半径受限：抽取失败回退纯正则；条款审查失败该层置空，共识层只剩数值复核条目；模型不可用时核对与范围内问答在入口就被拒绝（服务层抛错、CLI 退出码 2、界面拒绝），不产出残缺结论。每个降级都显式标注并落库，系统不会把模型缺席伪装成正常结论；反过来，模型的发挥空间也永远出不去核验的包围圈。

## 模型输出的程序核验

### 条款判定：六道核验

1. 等级合法：只接受 A / B / C，其余直接丢弃。A 级另需三件套齐全——法条 ID、证据原文、法条原文摘抄（`quote_statute`）；缺摘抄降为 B，不丢整条。
2. 证据可定位：证据必须是合同原文中 10–100 字的连续片段，不得改写、拼接、跨段落；长度不符或定位不到即丢弃。
3. 法条在库且原文回声：引用条号必须存在于 143 条法源库，库外引用丢弃；`quote_statute` 必须是所引法条原文的连续子串，抄错则清空该引用（A 级随之降 B）。
4. 引用闭集：触发器候选的引用不得越出随候选下发的法条闭集，模型不得自由引法，越界丢弃。
5. 缺依据降级：A / B 级没有法条依据的，一律降为 C 级。
6. 重叠不足降级：模型证据与候选片段的重叠比例低于下限，视为可能看错条款，降一级（只降不升），片段位置仍以候选为准。

丢弃与降级是两类处理：等级非法、证据不合格、库外引用、越出闭集属于丢弃；缺摘抄、缺依据、重叠不足属于降级或清空引用，结论保留但等级下调。每条丢弃与降级都写入诊断信息，随任务落库，可事后审计。评测脚本另设关闭核验的消融臂，用来度量"没有核验层模型会输出什么"，该臂只用于评测，不用于生产展示。

### 追问：八道核验

1. 字段闭集：只能挑本轮待补范围内的字段，越界丢弃。
2. 去重：同一字段只保留一条。
3. 条数上限：超上限按序截断。
4. 阻断项全覆盖：模型漏问的阻断项用固定问句补齐。
5. 问句形态：单行不含换行、字数在规定区间、以问号结尾。
6. 禁引法条编号：追问不向用户甩条号。
7. 禁结论性说法：追问不得预判核对结果。
8. 数值一致：问句里的数字必须来自已填事实或该字段的固定问句，其余视为编造。

任一条不过，只有该条退回固定问句，不牵连其他条目；模型调用整体失败时全部使用固定问句。追问环节永不抛异常。

### 可溯源校验（verify 节点）

每条结论与建议的 `source_id` 必须落在"规则表法条与规则 ID ＋ 本轮检索命中"的允许集合内，校验器按 100% 强制执行——这是输出的放行条件，不是目标值。建议类条目无依据则拒绝生成。任何一条说不清来源，整次结果走 degrade：结论保留但标记"依据不足"，错误清单随任务落库。该节点跑在图主干上；条款判定的结论另有各自的把关——引用必须落在候选闭集内、条号必须在 143 条库内、摘抄必须是法条原文子串，由 `clause_review` 在进共识层之前完成。

### 消融开关

核验与分层不只是设计说法，还做成了可拆装的开关，供评测逐层度量贡献：`MLA_EXTRACT_MODE` 控制抽取档（`regex` 档纯代码、离线可复现，测试固定用这一档），`MLA_CLAUSE_REVIEW` 控制条款判定这一层整体启停，`MLA_ALLOW_NO_LLM` 显式放行无模型的离线旧路径（仅供测试与诊断），评测脚本另可按 `--variant` 拆臂（`rules_only` / `rules_retrieval` / `llm_only` / `full`，默认 `all` 连跑其中三臂）。条款级评测还设有关闭程序核验的模型裸输出臂。各臂指标与结果见 [evaluation.md](evaluation.md)。

### 隐私口径（与核验同级的设计约束）

按外发内容分四条路径，逐条写死：

| 路径 | 发送给模型的内容 | 不发送的内容 |
|---|---|---|
| 抽取（LLM 档） | 合同正文（上限 `MLA_EXTRACT_MAX_CHARS`，默认 20000 字） | — |
| 条款审查（`services/clause_review.py`） | 被触发器召回的候选条款原文 + 其前后各 2 行邻近段落 | 合同全文与无关段落（姓名、住址、身份证号、工资数等） |
| 检索（含向量 `dense_query`） | 只发送问题本身 | 合同正文、条款片段、结构化事实 |
| 追问 / 问答 | 问题 + 本次核对的结构化摘要（事实、规则命中、条款段落号与等级、命中法条） | 合同正文、条款片段原文 |
