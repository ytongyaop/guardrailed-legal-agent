# 005 结果页信息架构收敛（0.3.x）

基线：v0.3.0（`324b814`）。本文规定信息架构，Streamlit 仅用于验证，0.4.0 新前端须复现同一行为。
行号以 v0.3.0 为准，实施时按函数与内容定位，不按行号机械修改。

## 目标

在不改变任何核对结果的前提下，使结果页默认只呈现结论与可展开依据，并通过一个持久化开关统一控制过程信息，且新旧任务、现有导出与全部既有行为保持兼容。

### 2. 三层归属

| 层 | 用户要回答的问题 | 信息与呈现规则 |
| --- | --- | --- |
| 第一层 结论 | 这份合同有几条确定冲突、几条待确认，具体是哪些？ | 原 `headline`、确定冲突/待确认的结论性计数与条目默认可见；不把两类加成一个风险总数 |
| 第一层 结论 | 每条结论引用哪条法律？ | 法名与条号常驻；即使原文折叠，仍能看到如“《劳动合同法》第十七条” |
| 第一层 结论 | 下一步怎么处理？ | 处理建议正文及依据默认可见，不折叠；删除的只是顶部“处理建议数量”指标，不是建议内容 |
| 第一层 结论 | 第十七条九类必备条款缺了哪些？ | 独立区块列出缺失/未见/需人工确认及各自计数，不并入冲突或待确认条数 |
| 第二层 依据 | 我怎样核验这条结论？ | 法条原文、施行日期与来源链接默认折叠；条号留在折叠器外 |
| 第二层 依据 | 同类情形如何认定？ | 类案参照整体默认折叠；保留“不构成本案结论”及来源信息 |
| 第三层 过程 | 系统怎样得到这次结果？ | 耗时、引用条文数、覆盖率明细、规则/模型与 A/B/C、共识 `note`、补问轮数及追问正文、降级、可溯源、抽取提示、任务/Token/问答运行详情，统一受开关控制 |

补充归属：合同未约定、需补充事实、法定兜底和“合同正文较短，结论可能不完整”仍属第一层，因为它们决定下一步或结论边界；“依据事实”属第二层折叠内容。法条引用是依据，不得因隐藏“判定来源”而隐藏。`Verdict.details` 中只把 `规则 x/y 可判定`、条款审查运行状态、缺事实无法判定数、`必备条款 x/8 已写`、必备条款区的 `已写 x 类` 及 `_clause_review_note` 移到第三层；结论计数与上述限制提示仍在第一层，原文保留且不重复渲染。

第三层是可见性分类，不要求所有内容塞进同一个容器：数值/状态/运行详情归入独立“查询路径与判定来源”区，条目来源徽标、内部等级、来源 help 与共识 `note` 可留在所属条目旁，但必须与该区同时出现或消失。开关不得改变第一层的内容、数量或顺序。

### 3. 默认态与开关态页面骨架

默认态（设置缺失或为 `0`；第三层不调用渲染，而非仅视觉折叠）：

```text
结果页
├─ 第一层 结论
│  ├─ 原结论句＋结论性计数＋原结论提醒
│  ├─ 核对结论（高/中/低；条目内容、分级与顺序不变）
│  │  └─ 每条：结论内容/片段/理由/常驻条号；新路径保留确定性徽标＋[依据：原文，折叠]
│  ├─ 合同未约定/需补充事实/法定兜底（原有内容）
│  ├─ 必备条款完整性（独立；常驻条号＋[依据：原文，折叠]）
│  ├─ 处理建议（完整正文，不折叠）＋导出 Word
├─ 第二层 依据
│  ├─ 依据事实（折叠）
│  └─ 类案参照（折叠）
├─ 就本合同继续提问（原提问交互；结论/建议不变，原文折叠，无运行详情）
└─ 原免责声明（仍只出现一次）
```

开关态（值为 `1`；前两层与默认态逐项相同，仅在下列位置增加内容）：

```text
结果页
├─ 第一层 结论（与默认态相同；条目旁可增加来源/内部等级/共识 note）
├─ 第二层 依据（与默认态相同）
├─ 第三层 过程：查询路径与判定来源
│  ├─ 引用条文数、耗时、全部覆盖率明细
│  ├─ 可溯源、补问轮数与追问正文、降级、抽取提示
│  └─ 任务编号、Token、运行详情；问答产生后也显示其运行详情
├─ 就本合同继续提问（原交互）
└─ 原免责声明（位置与文本不变）
```

### 4. 设置项定义

| 项 | 规定 |
| --- | --- |
| 键名 / 存储 | `ui.show_query_path`；现有 `settings` 表，经 `get_setting` / `set_setting` 读写 |
| 值 / 默认值 | 仅 `1` 为开；`0`、空串、缺键及未知值均为关；不在读取时回写数据库 |
| 文案 | 复选框“显示查询路径与判定来源”；帮助“显示耗时、覆盖率、判定来源、补问与运行详情；不影响核对结论。” |
| 位置与作用域 | 设置页新增“界面设置”，所有角色可用；管理员顺序为模型/界面/账号，普通用户为界面/账号。全库一个全局开关，不按用户或任务保存 |
| 生效 | 切换时立即 `set_setting` 并重绘；重新打开页面或新建仓库实例后仍保持，不重跑核对、不改任务记录 |

### 5. 不做什么

- 不改判定逻辑、条目内容、数量、影响度、确定性、排序、覆盖口径，不在 UI 重新实现 `summarize_verdict` / `sort_items`。
- 不改免责声明、处理建议免责、确定冲突/待确认对外词，不把过程状态表述为结论；不隐藏拒答原因。
- 不改 `domain/`、`services/`、法源/规则/评测数据、Word 报告、历史列表/筛选/趋势、问答生成与隐私上下文。
- 不加表、列、迁移、用户级偏好或第三方依赖；旧任务不回填、不重算，缺失字段按无处理，不伪造 `0` 或“已运行”。
- 不做 FastAPI、Vue、接口迁移或视觉设计 overhaul；本轮仅移动、折叠、分组和加开关。

### 6. 对 0.4.0 的交接

新前端必须复现：三层语义与渲染顺序、默认关闭且持久化的全局开关、第一二层不随开关变化、条号独立于原文折叠、建议不折叠、必备条款独立计数、过程信息统一显隐、旧记录空值容错、原免责与对外口径。接口应直接提供领域层结论和已排序展示条目，前端不得用 JavaScript 重写计数、分级或排序。

无需复现：`st.expander/popover/container`、控件 key、`session_state`、rerun、AppTest 节点结构、具体函数签名及 Streamlit 布局参数。可用 Vue 的折叠面板/设置开关实现，但不得把“关闭时不渲染过程信息”退化成仅 CSS 隐藏。
