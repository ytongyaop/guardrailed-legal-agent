## 1. 问题陈述：为什么现在的优先级错了

### 1.1 真实合同上规则通道的表现（无事实跑 `judge_all`）

| 合同 | 字数 | 规则命中 | 可判定 | 触发器召回 |
| --- | --- | --- | --- | --- |
| `contract_traps_01.txt` | 1837 | 0 | 0/20 | 22 条 / 21 类 |
| `contract_traps_02.txt` | 1295 | 0 | 0/20 | 9 条 / 9 类 |
| `contract_traps_03.txt` | 999 | 0 | 0/20 | 12 条 / 10 类 |
| `contract_compliant_01.txt` | 1274 | 0 | 0/20 | 0 条 / 0 类 |

带正则抽取事实后（`run_check`），`traps_01` 升到 12/20 可判定，**命中仍是 0**。

> 口径说明：表中 `/20` 与上句 `12/20` 是**迁移前实测**（当时规则表 20 项）。第 5.3 节把规则表瘦身为 16 条后，同义表述变为 `/16`；被删的 4 条判定对象是合同外事实（`field_catalog.py:84-86` 标 `external`），在 4 份合同上本就进不了"可判定"，因此 0 命中、0 可判定的结论不因瘦身而改变。

对照组 0 命中是正确表现（全合规合同本就不该命中）；三份对抗合同同为 0，才是问题所在。

### 1.2 现有评测集的表现

| 项 | 实测值 |
| --- | --- |
| `eval_cases.jsonl` 用例数 | 52 |
| `rules_only` 臂 风险/缺项召回率 | 1.0000 |
| 用例 kind 分布 | violation 20 / compliant 8 / deficient 6 / complete 6 / boundary_out 6 / boundary_in 6 |
| `gold_items` | 32 例为 0，20 例为 1 |

52 条里 32 例根本不要求命中任何条目；剩下 20 例每条只考一个数值点。1.0000 说明的是"出题人只出了规则会做的题"，不说明真实合同能力。README:152 与 evaluation.md:32（"满分不能读成准确率 100%"）把这件事并列写出，却仍把 1.0000 放进能力表——这就是**指标幻觉**。

### 1.3 三个诊断必须分开

| 诊断 | 判断 | 依据 |
| --- | --- | --- |
| 规则**机制**差吗 | 不差 | 规则表当前有阈值两侧边界回归（`tests/test_rule_boundaries.py`），`rules_only` 臂召回 1.0000；纯函数、可复算、零成本；瘦身后保留 16 条同样带边界回归，删掉的 4 条连用例一并下线（5.3） |
| 规则**适用域**窄吗 | 是，结构性窄 | 规则只能表达"法条明文写了数字或枚举、且合同里能抽到该数字"的形态；对抗合同的违法形态是"放弃社保""加班费按基本工资计基数""试用期随时解除"——存在性与语义问题，规则表无字段可表达 |
| 优先级错在哪 | 把**覆盖面 0** 的通道当**基准** | 无模型时规则是唯一结论来源（README:86-88），于是系统输出的是"12/20 判不了 + 命中 0"的残次结论 |

**结论**：规则的价值在"可复算的数值校验"，不在"判定覆盖面"。把规则放在基准位置，等于用一个结构性召回 0 的通道当主判官——这就是作者说的"没有大脑，跑出来的都是残次品"。

## 2. 目标与非目标

### 2.1 目标（可测）

| # | 目标 | 可测判据 |
| --- | --- | --- |
| G1 | 模型成为主判定通道 | 一条合同的用户可见结论，其条目来源必须是模型结论（经核验）或共识层，不得是裸规则命中 |
| G2 | 规则/脚本成为约束器与数值校验器 | 规则输出只有 `ok / mismatch / needs_fact`，不产生"这是风险"的独立结论 |
| G3 | 无模型时核心核对不可用 | 无 Key 时核对入口被拒（UI 不渲染、CLI 非零退出），不产出残缺结论 |
| G4 | 可追溯与隐私口径不放宽 | 每条结论仍有 `source_id` 或候选闭集引用；外发范围仍是候选 ±2 行 |
| G5 | 评测指标换成有真实分母的集合 | 主指标来自 `clause_gold` 95 条（38 正 / 57 负），带 Wilson 区间与"开发集"声明 |

### 2.2 非目标（本轮明确不做）

| # | 非目标 | 理由 |
| --- | --- | --- |
| N1 | 不做 autonomous planning / 自主路由 | 与 `docs/architecture.md:29`"模型没有任何通道改变图结构或路由条件"一致；反转的是**判定归属**，不是流程控制权 |
| N2 | 不做 multi-agent 协作 | 同上，项目口径是受限智能体 |
| N3 | 不整体删除规则表 | 规则表瘦身后保留 **16 条**数值校验规则，删除 4 条行为义务 / 行政主体规则（清单与理由见 5.3）；规则从此不再当判官 |
| N4 | 不做端到端模型直出 | 六道核验必须保留，否则错误半径失控 |
| N5 | 不改隐私口径 | 仍只发候选 ±2 行与法条原文，不发合同全文 |
| N6 | 不改 `clause_gold` 标注、不改触发器的召回口径（`patterns` / `candidate_statute_ids` / `severity_hint`）；L2 改为独立的要素骨架文件（4.3），`triggers.yaml` / `rules.yaml` 一个字段不加，候选数不得变化 | 否则评测与实现同源，指标失去意义 |

## 3. 四处反转（核心）

### 3.1 编排顺序：规则先 → 模型先，规则后置校验

| 维度 | 现在 | 反转后 |
| --- | --- | --- |
| 谁先出结论 | `graph/nodes.py:208` `rule_check` 在 `retrieve` 之后、`checklist` 之前，`items` 由违规规则直接生成（:229-241） | 先跑候选召回 `domain/clauses.py:159` `detect_clauses` → 模型逐条判定 → 核验 `services/clause_review.py:285` `_verify` → 出 `ClauseFinding` |
| 条款审查的位置 | 图外：`services/tasks.py:149` `_review_clauses` 在图跑完后追加（architecture.md:62） | 提到主链路，成为结论的主要来源；规则校验与 findings 在同一汇总层对齐 |
| 规则何时介入 | 最早，且是唯一结论源 | 最后：作为后置校验信号，与模型结论逐条比对（新增共识层） |
| 展示顺序 | "规则判定 → A → B → C"（architecture.md:72） | 先按**影响度**（高 → 中 → 低），同影响度内按**确定性**（确定冲突 → 待确认），再按**来源**（有段落的法条明文冲突 → 无段落的数值校验条目）、段落号升序；规则校验一致/冲突作为**标签**挂在条目上，不再占位，也不再对外展示 A/B/C（见 3.4） |

编排约束：**图仍是 13 个固定节点**（architecture.md:27），不新增自主路由；只把 `rule_check` 的职责从"出结论"改成"出校验信号"，并新增一个纯函数共识层 `services/consensus.py`（无模型调用、无分支决策）。

### 3.2 规则身份：独立判官 → 校验器

| 维度 | 现在 | 反转后 |
| --- | --- | --- |
| 状态枚举 | `rules.py:160-170` `RuleStatus` 四态：violated / compliant / not_applicable / unknown | `RuleCheck.status` 三态：`ok / mismatch / needs_fact` |
| 用户可见语义 | `violated` 直接变成风险条目文案"XX 不得超过 1 个月（实际 3 个月）"并标"规则判定·确定性" | 文案只表达"数值与第 X 条不一致"，不写"这是风险"；风险定性由模型结论承担 |
| 数量口径 | 规则命中数当能力指标（README 三层判定表） | 规则校验不再是能力指标，只报"校验覆盖数 / 冲突数 / 待补事实数" |
| 判不了怎么办 | `unknown` 拆四类分流（合同未约定 / 法定兜底 / 待补事实 / 可选），仍占用户视野 | `needs_fact` 统一并入追问候选字段，不出结论 |

### 3.3 门禁：无模型时核对入口拒绝

| 位置 | 现状（已核实） | 本规格要求 |
| --- | --- | --- |
| UI | **已另行实施**：本仓库工作区 `src/mla/ui/app.py:701-714`，`_page_check` 在 `_resolve_llm(...) is None` 时只显示提示并 `return`，不渲染核对入口 | 保持；文案不改（"未配置模型，合同核对不可用；配置后才能给出结论"） |
| CLI | 未实施：`cli.py:113` `cmd_check` 无门禁，`cli.py:128-132` 无 Key 时 `generator=None` 仍跑规则出结果 | 新增：服务入口强制断言，无模型时**非零退出码** + 指向设置页/环境变量的错误 |
| 服务层 | 无：`services/tasks.py:70` `run_check` 可被任何调用方在无模型下调用 | 新增：`run_check` 前置断言（唯一真门禁，UI 与 CLI 都是它的调用方） |

衔接声明：本节与"已实施"的 UI 门禁不冲突——**UI 是友好提示，服务层是硬门禁**。已实施部分作为 P0 的既有输入，不重复改动。

### 3.4 分级重构：影响度为主，确定性只两层

> **变更（2026-11-17）**：对外两层改为 `确定冲突` / `待确认`——A 级与规则数值校验条目（`source=rule_check`，程序算出的数值不一致）为“确定冲突”，B 级与 C 级归入“待确认”。排序在确定性之后新增“来源”键：有段落定位的 A 级先于无段落的数值校验条目。

原口径把 A/B/C 三级直接给用户看（A＝法条明文禁止 / B＝需补充事实或含裁量 / C＝待确认）。问题有两层：**用户要解码字母**；而且 **A 与 B 对用户而言下一步动作相同**（都是"改"，或"把事实问清后改"）。新口径拆成两个维度：

| 维度 | 取值 | 作用 | 谁决定 |
| --- | --- | --- | --- |
| **影响度**（主） | `高` / `中` / `低` | 决定排序与视觉权重 | **合同要素属性**（4.3 的 13 要素各带默认值），不由模型自由判 |
| **确定性**（次） | `确定冲突` / `待确认` | 决定这条是“已确认的不一致”还是“还需人判断” | 由内部 `grade` + 条目来源机械映射，纯函数 |

内部等级与对外两层的映射（**A/B 区分在模型内部继续存在**，只服务六道核验与降级链，不再对外）：

| 内部 `grade` / 来源 | 对外确定性 | 用户看到的形态 |
| --- | --- | --- |
| A（法条明文禁止 + 三件套齐全） | `确定冲突` | 直接列在“确定冲突”区，**不做额外提示** |
| 规则数值校验（`source=rule_check`，内部 `grade=C`） | `确定冲突` | 与 A 级同层，标注“程序数值校验”；无合同段落，排在同层 A 级之后 |
| B（需补充事实或含裁量） | `待确认` | 列在“待确认”区；`need_facts` 作为该条目内的追问提示 |
| C（现有事实不足以下定性） | `待确认` | 同上，不占“确定冲突”位 |

不把 B 并入冲突层的理由：B 是"需补充事实或含裁量"，把待核实说成确定结论会误导用户；而规则数值校验条目虽然内部也是 C，但它是程序按法条数值算出的确定不一致，应当与 A 同层。内部等级仍有硬用途——A 要求 `statute_ids` + `quote_statute` + `evidence` 三件套齐全，A 带 `need_facts` 会被第 5 道核验强制降 B，这些降级链不应暴露到用户面前。

**影响度怎么定（不主观打分，由"合同要素 × 法律后果类型"推导）**：

| 影响度 | 推导条件 |
| --- | --- |
| 高 | 涉及**钱**（工资、加班费、经济补偿 / 赔偿、违约金、社保缴费）；涉及**解除权或存续期限**（试用期、竞业限制、保密义务与期限）；涉及**工伤与连带责任** |
| 中 | 涉及**程序义务**（登记、备案、通知、送达、审批流程） |
| 低 | **形式瑕疵与措辞不规范**（称谓不统一、表述含糊、条款编号混乱，但不改变权利义务） |

**取值唯一来源是要素**：4.3 每个要素带一个"影响度默认值"，条目证据落在哪个要素的段落就取该要素的值；一条证据同时命中多个要素时取**最高**值。模型可给建议值（`impact_suggest`，6.2），但只要与要素值不一致，**以要素值为准**并记诊断。规则表里**不写**影响度（第 5 章）；模型也**不能**自由判影响度。

**排序规则（确定性、可测，不引入主观权重）**：

```
第一键 影响度：高 > 中 > 低
第二键 确定性：确定冲突 > 待确认
第三键 来源：法条明文冲突（有段落） > 程序数值校验（无段落）
第四键 合同段落号：升序
```

计算位置：纯函数 `domain/grading.py`（新增）`to_display(finding, element) -> DisplayLevel`，零模型、可复算；在共识层（5.4）产出最终条目时调用一次，界面与导出都只消费它的结果。

## 4. 四层职责划分（规则级 / 辅助层 / 校验层 / 返工）

第 3 章反转的是**判定归属**（模型判、规则校验）。但"模型主导"如果不配约束，等于把错误半径放大到全量。作者口径把约束拆成三层 + 一个纠错回路，本章是整份规格的骨架，第 5–7 章都挂在它下面。

### 4.1 四层总览

| 层 | 职责 | 谁执行 | 具体内容 | 失败时 |
| --- | --- | --- | --- | --- |
| **L1 规则级** | 约束模型**输出形态**（写什么、取值范围） | 程序：prompt 模板（`clause_review.py:45` `REVIEW_SYSTEM`）+ schema 参数（`:458` `generate(..., {"type": "object"})`）+ 字段清单 | 必须带法条 ID（`statute_ids`）、法条原文摘录（`quote_statute`）、等级（`grade`，仅 A/B/C）、证据片段（`evidence`，10–100 字）、`reason`（≤ `MAX_REASON = 200`，`:39`）；字段缺一不可 | 由 L3 检出 → 进 L4 返工；L4 到上限仍不过 → 丢弃该条 + 记诊断 |
| **L2 辅助层** | 提高**命中率**（把模型注意力压到合同的要素结构上） | 数据（`src/mla/data/clauses/elements.yaml` 13 个要素骨架）+ prompt 模板 | 每个要素给"要素名 / 段落特征 / 判断方向 3–5 条 / 影响度默认值"；按本批候选所在段落匹配后随 payload 注入（见 4.3）；**不含任何数值、期限、百分比与法条条号** | 不产生"失败"概念：只影响命中率，效果由 `clause_gold` 覆盖率与消融对照组观察 |
| **L3 校验层** | 只做**可机械判断**的校验 | 纯函数（零模型、可复算、可断言） | **L3.1 确定性校验**：数值区间（规则阈值两侧）、条号在库、引用闭集、证据可定位、长度（详见第 7 章六道 + 第 5 章 `RuleCheck`）；**L3.2 行为校验**：模型是否守 L1 的字段与格式约定（详见 7.2） | 可修正 → L4；不可修正 → 直接丢弃 |
| **L4 返工** | 把机械失败**回喂模型重试** | 编排层（`clause_review.py:455-469` 批次循环内，`_collect` 之后） | 回传"哪一项校验没过 + 期望值 + 实际值"；上限 2 次；仍不过则丢弃该条或降 C，并记诊断 | 达上限 → 丢弃该条，`errors` 留痕（`models.py:295`） |

三条硬边界（本规格口径，后文所有校验条款都按它判归属）：

1. **L3 只装"脚本能精准命中"的校验**。判定标准是"同一份输入，两个独立实现跑出同一结论"。凡需裁量（这条到底算不算违法、理由写得够不够好、等级该不该更高）**一律不进 L3**——那是模型的事，规格不假装能脚本化。
2. **L4 只对可机械判定的失败返工**（字段缺失 / 格式错 / 引用越界 / 长度越界 / 条号不在库）。**不对"内容质量"返工**：内容质量没有客观终止条件，返工必然退化成无限循环。
3. **返工有成本**：每批多一次模型调用，延迟与费用随之上升。因此设上限 2 次，并把重试次数记进任务指标（4.5.5），让评测能看见这笔账。

### 4.2 L1 规则级（约束什么写、不约束写得对不对）

| # | L1 约束 | 具体内容 | 落点 | 不过时 |
| --- | --- | --- | --- | --- |
| 1 | 必须带法条 ID | `statute_ids` 非空（A/B 级强制；C 级可空）；每条 ID 必须是 143 条库内条目 | `REVIEW_SYSTEM:45` 措辞 + 6.2 schema | L3.2 判形态失败 → 返工 |
| 2 | 必须带法条原文摘录 | `quote_statute` 逐字抄被引条文（归一化后须是库内 `text` 的连续子串）；`statute_ids` 与 `quote_statute` 一一对应 | 同上 + `_verify:321-324` 加严 | L3.2 判缺失 → 返工；L3.1 判非子串 → 清空引用后按六道降级 |
| 3 | 必须带等级且值域封闭 | `grade ∈ {"A", "B", "C"}`（`GRADES = ("A", "B", "C")`，`:37`）；自提条目封顶 C | `_verify:306-309` | L3.2 判越域 → 返工 |
| 4 | 必须带证据片段 | `evidence` 逐字连续抄合同原文，长度 10–100 字 | `_verify:310-314` + `_locate:84` | L3.2 判长度越界 → 返工；定位不到 → 不可修正，丢弃（见 4.5.3） |
| 5 | 字段缺一不可 | 必填：`idx` / `grade` / `reason` / `statute_ids` / `evidence`；可选：`quote_statute`（A/B 实为必填）/ `need_facts`（≤ `MAX_FACTS = 5` 条、每条 ≤ `MAX_FACT_CHARS = 80`）/ `numeric` / `self_check` | 6.2 表 | L3.2 列出缺失字段 → 返工 |
| 6 | 长度上限 | `reason ≤ MAX_REASON = 200`；`need_facts ≤ 5` 条；单条 ≤ 80 字；证据 10–100 字 | `:39-41` | L3.2 判越界 → 返工（可截断的按截断后重交） |

L1 只约束**形态与值域**，不约束"内容对不对"——内容命中率靠 L2 拉，内容对错里可机械的部分靠 L3 拦，其余由六道的降级链与人工复核兜。**L1 不是"再写一遍规则文本"**，而是把要求固化成"模板措辞 + 字段清单 + 值域枚举"，并且每一条都能被 L3.2 机械判出"守没守"。

### 4.3 L2 辅助层（合同要素骨架：13 个要素，不含任何数值）

**性质**：提示词工程 + 结构提示。不改判定权、不进校验、不产生条目、不改变召回。

**为什么从"写法枚举"改成"要素骨架"**：原方案是给 33 条触发器各配 `checklist` / `pitfall`，本质是**枚举一句话有几种写法**——穷举永远追不完（同一层意思可以写成十种表述）；而且每条都塞数值与条号，一遇**地区实施细则差异**或**法律修订**就要全表返工。劳动合同的**结构**是稳定的：任何一份合同都由同样十几个部分构成。把提示压到结构上，模型自己在段落里找具体写法；数值与条号则交给 L1（引用）与 L3（校验）去管——**数值只允许出现在 L1 必须引用的法条原文里，和 L3 的校验阈值里**。

**数据形态**：新增 `src/mla/data/clauses/elements.yaml`，13 个要素，每个要素四个字段：

| 字段 | 含义 | 写法约束 |
| --- | --- | --- |
| `name` | 要素名 | 固定 13 个（见下表） |
| `section_hints` | 该要素在合同里的**段落特征**（标题或段首标志词，2–5 个） | 只写"怎么认出这一段"，不写"这一段有几种写法" |
| `focus` | 模型需要判断的方向，3–5 条 | 只写"要看什么、要分清什么"，**不写结论、不写阈值** |
| `impact` | 影响度默认值（`高` / `中` / `低`） | 取值规则见 3.4；一条证据命中多个要素时取最高 |

**13 个要素（顺序即劳动合同通常的叙述顺序）**：

| # | 要素 | 段落特征（形态，非写法枚举） | 影响度默认值 |
| --- | --- | --- | --- |
| 1 | 当事人与基本信息 | 首部：双方名称、住所、证件号、联系方式 | 低 |
| 2 | 合同期限（固定 / 无固定 / 完成一定工作任务） | 标题含"期限"；"自…至…"的起止表述 | 高 |
| 3 | 试用期（有无、时长、次数） | 标题含"试用"或段首出现"试用期" | 高 |
| 4 | 工作内容与地点（岗位、职责、地点、是否可调岗） | 标题含"工作内容""岗位""地点"；出现"调整" | 高 |
| 5 | 工作时间与休息休假（工时制度、加班、休假） | 标题含"工时""工作时间""休假""休息" | 高 |
| 6 | 劳动报酬（构成、支付周期、支付方式、加班费） | 标题含"工资""报酬""薪酬"；出现"发放""支付" | 高 |
| 7 | 社会保险与福利 | 标题含"社会保险""社保""福利" | 高 |
| 8 | 劳动保护与职业危害 | 标题含"劳动保护""职业危害""安全""防护" | 高 |
| 9 | 保密与竞业限制 | 标题含"保密""竞业" | 高 |
| 10 | 培训与违约金 | 标题含"培训""服务期""违约金" | 高 |
| 11 | 变更、解除与终止 | 标题含"变更""解除""终止""辞职""辞退" | 高 |
| 12 | 违约责任与争议解决 | 标题含"违约""争议""仲裁""诉讼" | 中 |
| 13 | 其他约定 | 兜底：前 12 项都没命中的段落 | 中 |

第 12 项给"中"而不是"高"：违约责任与争议解决属**事后救济程序**（选仲裁还是诉讼、走哪个机构），按 3.4 的"程序义务 → 中"落地；其中真正涉钱的部分（违约金数额）会落在第 4/6/10 项的段落上，按"多要素取最高"自然升到"高"。

第 13 项（兜底）给"中"而不是"低"：兜底**不暗示"不重要"**——归不到类的段落是分类器没认出来，不是形式瑕疵；按"中"处理可避免真实条款被压到列表底部（与 `domain/grading.py` 对未知要素按"中"的守卫同口径）。

**示例：两个要素的完整写法**（`focus` 只写方向，不含数字、条号与写法枚举）：

```yaml
- element_id: EL-3
  name: 试用期
  section_hints: ["试用", "考察期"]
  focus:
    - 这一段有没有约定试用期（约定与不约定是两件事，不约定不是缺陷）
    - 试用期是单独写，还是与合同期限 / 转正条件混写（混写会让起点与终点都变模糊）
    - 试用期与合同期限的关系有没有交代（期限类型不明时，试用期长度无从核对）
    - 试用期有没有被约定成"可以再约定 / 可以延长"（次数结构问题）
    - 试用期内的工资、社保、解除条件是否单独交代
  impact: 高

- element_id: EL-9
  name: 保密与竞业限制
  section_hints: ["保密", "竞业"]
  focus:
    - 保密义务的对象与范围有没有界定（商业秘密 / 经营信息 / 客户资源）
    - 竞业限制是否与"离职后"绑定，还是混在在职期间的保密义务里
    - 竞业限制的适用范围、地域、岗位层级有没有交代
    - 单位一侧的补偿义务有没有出现（只写劳动者义务、不写单位义务是常见漏项）
    - 保密义务与违约金 / 赔偿是否被混为一谈
  impact: 高
```

**明确禁止（写成可脚本检查的规矩）**：

| 禁止项 | 不得出现的形态 | 为什么 |
| --- | --- | --- |
| 具体数值、期限、百分比 | "试用期不得超过 6 个月"、"30 日内"、"3 倍" | 数值随地区实施细则与法律修订变化，写死在提示层＝每次修订都要改全表 |
| 法条条号 | "依据第十九条"、"第三十一条规定" | 条号只在 L1（必须引用且须过原文核验）与 L3（在库 / 闭集校验）出现；提示层写条号会把"引用"退化成"抄提示" |
| 写法枚举 | "包括但不限于以下 8 种表述：…" | 穷举追不完，且把模型推向"按清单找字面"而不是"读结构" |

校验方式（可脚本化）：`elements.yaml` 不得出现阿拉伯数字、`第…条`、百分号——`Select-String -Pattern "\d|第[一二三四五六七八九十百]+条|%"` 计数为 0。允许中文数量词（如"再约定一次"），因为它判的是**次数结构**，不是阈值。

**注入方式**：`_payload:200-225` 组 payload 时新增顶层键 `elements`——取本批（`batch_size = 5`）候选所在段落命中的要素骨架，每项含 `element_id` / `name` / `focus` / `impact`；候选字典（`:211-218`）新增 `element_id` 指向它（候选构造在 `:181`）。段落与要素的匹配是**纯程序**：对段落首行与段首 40 字做 `section_hints` 关键词匹配，命中即打标签；多个要素命中取最先命中者；全不命中落 `EL-13`。**只发本批命中的要素（通常 1–3 个）**，不发 13 个全表——否则提示会淹掉 ±2 行候选正文（与 4.5.4 的隐私口径同源）。

**硬约束**：

| 约束 | 理由 |
| --- | --- |
| 只新增 `elements.yaml` 与 payload 的 `elements` 键；`triggers.yaml` / `rules.yaml` 的字段一个不加、一个不改 | 召回口径一变，`clause_gold` 与触发器同源，指标立刻失效（与 2.2 的 N6 口径一致） |
| 骨架只写"要确认什么 / 要分清什么"，不得写结论性断语（"此条违法""应判 A"） | L2 不进判定；写了断语等于把模型往预设答案推，A 级误报会上升 |
| 注入后 `validate_triggers.py` 与 4 份合同候选数必须不变 | 可回滚、可对照的唯一证据 |
| 要素骨架的 `impact` 是**唯一**影响度来源（另有兜底：未命中落 `EL-13` 取"中"，并把该段落号写进诊断） | 影响度若可由模型自由给，排序就失去一致性（3.4 口径） |

### 4.4 L3 校验层（只做可机械判断的校验）

| 子层 | 校验对象 | 内容 | 落点 |
| --- | --- | --- | --- |
| **L3.1 确定性校验** | 结论对象的**值域与依据** | ① 数值区间：`RuleCheck.status` 三态与阈值两侧（第 5 章）；② 六道核验：等级合法 / 证据可定位 / 法条在库 / 引用闭集 / 缺依据降级 / span 采信候选（第 7 章 7.1，**六条与加严细节不变**） | 纯函数：`_verify:285`、`_locate:84`、`to_rule_check`（第 5 章） |
| **L3.2 行为校验** | 模型的**输出行为**（守不守 L1） | 字段齐备性 / 字段类型 / 等级枚举 / 长度上限 / `quote_statute` 与 `statute_ids` 一一对应 / 非 JSON 或多层嵌套 / 自提条目越限（只检测、不返工） | 7.2（新增，与 L3.1 共用失败清单格式） |

**边界（写死，别扩展）**：

- L3 **不做**"内容对不对"判断（那要读法理），**不做**"理由是否充分"评分，**不做**"等级该不该更高"的裁量判断。
- L3 **不重写**模型文本：证据长度越界只要求重交，不替模型截断后当成模型输出采纳（截断会改变证据语义）。
- L3.2 与 L3.1 的分工按**对象**切，不按六道切：L3.1 校验"结论对象的值域与依据是否成立"，L3.2 校验"模型有没有按 L1 的约定把字段交出来"。第 1 道（等级合法）留在 L3.1 里，因为它判的是值域；L3.2 判的是"字段在不在"。

### 4.5 L4 返工（把机械失败回喂模型）

#### 4.5.1 流水顺序

```
模型输出 → L3.2 形态校验 → L3.1 确定性校验 → 汇总失败清单
        → 可修正? ── 是 → L4 返工（≤2 次）→ 重跑 L3.2 / L3.1
        │                          └─ 到上限仍失败 → 丢弃该条 + errors 诊断
        └─ 否 → 直接丢弃该条 + errors 诊断（不返工）
```

顺序固定为"先形态后值域"：形态不过时值域校验没有意义（缺 `statute_ids` 就无从查闭集）。

#### 4.5.2 触发条件（可修正白名单，只认这五类）

| # | 失败项 | `check` 标识 | 期望值（`expected`） | 为什么可修正 |
| --- | --- | --- | --- | --- |
| 1 | 字段缺失 / 空值 | `field_missing` | 列出缺失字段名 | 补一个字段即可，不动语义 |
| 2 | 格式错（非 JSON 对象、`findings` 非列表、`idx` 非整数或越界、等级不在枚举内） | `format` / `grade_enum` / `idx_out_of_range` | 合法格式与取值 | 格式是机械约定 |
| 3 | 引用越界：条号不在 143 条库，或超出候选闭集 | `citation_in_library` / `citation_closed_set` | 候选闭集 / 库内条号清单 | 换上闭集内的条号即可 |
| 4 | 长度越界：`reason > 200`、`need_facts > 5` 条、单条 > 80 字、证据不在 10–100 字 | `length` | 字数区间与条数上限 | 删改字数不改事实 |
| 5 | `quote_statute` 缺失或与 `statute_ids` 不对应（抄了别的条） | `quote_statute_mismatch` | 该条法条全文 | 重抄一次即可 |

> 阶段注记（证据长度）：**P2-2 阶段先按"丢弃"处理**（`_verify` 的硬校验在返工队列之前，越界即丢并记诊断）；**P2-7 接入 L4 返工队列后改为"返工"**（失败清单带 `check=length`、`expected` = "10–100 字"，上限 2 次仍不过才丢弃）。本注记用于消除本表与 P2-2 实现的表面矛盾：长度越界的"可修正"属性成立，只是修正通道是按阶段接线的。

#### 4.5.3 不可返工的失败（直接丢弃）

| 失败项 | 为什么不返工 |
| --- | --- |
| 证据无法在合同原文定位（`_locate:84` 返回 `None`） | 说明模型在**编造原文**，重试只会换一种编法；返工等于给它第二次编造机会 |
| 结论与候选所指条款**严重不符**（`_overlap_ratio` = 0，且证据定位到的是别处约定） | 这是"看错了条款"，不是"格式没守"；重问一遍也还是错，直接丢弃更省一次调用 |
| 自提条目超出整份合同 `max_extra = 3` 的配额 | 封顶是输出规模约束（`review_clauses:475-494`），不是可修正错误 |

> 注：六道第 6 道现有口径是"重叠 < 0.5 加降一级"（`OVERLAP_MIN = 0.5`，`:43`），其中 0 < 重叠 < 0.5 仍按降级处理；本节只把**重叠恰好为 0**且证据落在别处的情形改判为丢弃。该边界差异已列入未决问题 Q7，评审时确认。

#### 4.5.4 返工请求形态

返工不是重发整批，也不重发合同正文：只把**失败的原始行**与该批候选（沿用同一份 payload）回给模型，system 追加一段固定模板。

```json
{
  "round": 1,
  "failed": [
    {
      "idx": 2,
      "trigger_id": "TR-PROBATION-TERM-EXCEED",
      "check": "citation_closed_set",
      "expected": "候选闭集 [LCL-19]",
      "actual": "LCL-99",
      "fixable": true
    }
  ],
  "original": [ { "idx": 2, "grade": "A", "reason": "...", "statute_ids": ["LCL-99"], "evidence": "..." } ]
}
```

system 模板（固定措辞，不改语义）：`上一轮输出有 N 项未通过程序校验，请只修正下列问题并重新输出同一批结论 JSON；不得新增结论，不得删除未被点名的结论。`

隐私口径不变：只含候选 ±2 行（`_outline:184-193` 的 `focus` 始终生效），不发合同其余段落，不发姓名/证件号。

#### 4.5.5 上限、成本与诊断

| 项 | 值 | 说明 |
| --- | --- | --- |
| 返工上限 | **2 次/批** | 即一批最多 1 次原始 + 2 次重试 = 3 次调用；第 3 次仍失败 → 丢弃该条 |
| 达上限处置 | 丢弃该条，写 `errors`：`第 {batch_no} 批第 {round} 轮返工仍未通过：check={check}，expected={expected}，actual={actual}` | 保持与现有诊断同格式（现有诊断见 `:307`、`:313`、`:323`、`:329`） |
| 返工成功诊断 | 写 `errors`：`第 {batch_no} 批第 {round} 轮返工通过：{n} 项已修正（{check 列表}）` | 事后可审计"哪条靠返工救回来"，也让 V13 的断言有落点 |
| 降级例外 | 仅"降级类"失败（A 缺依据 → B、A 有 `need_facts` → B、模糊词 → C）**不返工**，按六道直接降 | 降级本身已是可接受结局，返工收益低于成本 |
| 成本指标 | `CheckTask` 新增**可选**字段：`clause_retry_calls: int = 0`、`clause_retry_items: int = 0`、`clause_retry_passed: int = 0`；不改现有必填字段（现有字段见 `models.py:268-309`） | 评测报"平均重试次数 / 返工通过率"；`token_in` / `token_out`（`models.py:305-306`）已能体现费用增量 |
| 开关 | `MLA_CLAUSE_RETRY`（int，默认 `2`，`0` = 关闭、等价旧行为） | 关闭即回滚到"校验失败直接丢弃"的老路径 |

## 5. 规则新契约：规则作为校验信号（最重要，必须可执行）

本章在四层里承担两件事：规则的数值判定是 **L3.1 的校验信号来源**——本章产出的 `RuleCheck` 也是六道之外那道"数值区间"校验的判定依据；规则的 `status` / `expected` / `actual` 随候选进入 payload 的 `rule_checks`（6.1）。L2 的要素骨架与本章无关：`rules.yaml` 一个提示字段都不加（见 4.3）。

### 5.1 数据结构（只给签名）

```python
# src/mla/domain/rules.py
class RuleStatus(StrEnum):
    OK = "ok"                # 数值落在法条合法区间
    MISMATCH = "mismatch"    # 数值与法条不一致
    NEEDS_FACT = "needs_fact"  # 事实缺失或不可解析，判不了

@dataclass(frozen=True)

def to_rule_check(outcome: RuleOutcome) -> RuleCheck: ...
```

### 5.3 规则层瘦身：保留 16 条（全部为数值校验）+ 删除 4 条

### 5.4 数值校验如何影响最终结论

| 规则校验状态 | 模型结论 | 处置（`reconcile` 返回） |
| --- | --- | --- |
| `mismatch` | A/B/C，且理由指向同一数值点 | `keep`；加标签"数值校验一致"，等级不升不降 |
| `mismatch` | 未提及该数值点 | 追加一条内部 `grade=C`、`source=rule_check` 的条目（对外显示为“确定冲突”，见 3.4），文案"数值与第 X 条不一致，请核对合同约定"，`verdict=review_required` |
| `mismatch` | 模型说"合规/未发现问题"（方向相反） | 保留模型条目但降一级（A→B、B→C），加标签"模型与数值校验冲突"，`verdict=demote` |
| `ok` | A/B，且理由只涉及该数值点 | 降一级（A→B、B→C），`verdict=demote`；记诊断"模型结论与数值区间矛盾" |
| `ok` | A/B/C，理由涉及其他事由 | `keep`，仅记诊断，不动等级 |
| `needs_fact` | — | 不出结论；字段并入追问候选（`services/asking.py` 既有闭集机制） |

降级只允许向下（A→B→C），不允许任何流程把等级升上去——升等级的唯一途径是模型自己给（且过核验）。

> 提示级规则已全部下线（5.3 的 4 条删除），因此不再有"附注 / annotate"这一处置：`reconcile` 的 `verdict` 收敛为 `keep / demote / review_required`。对外两层（3.4）只影响展示：A→B 会从“确定冲突”移到“待确认”，B→C 仍留在“待确认”；降级不会把条目升回冲突层。

### 6.1 输入（在现有 payload 上加强）

现状：`clause_review.py:200-225` `_payload` 发送 `contract_paragraphs`（`_outline:184-193`，候选 ±2 行）与 `candidates`；每个候选带 `statutes`（`:165-181` `_statutes_payload`，每条法条摘录上限 `STATUTE_EXCERPT = 200` 字符）。

### 6.4 L1 字段清单与检出层的对应（每条都能机械判）

L1 的每条约定都必须有唯一检出层，否则"规则级"就只是愿望。对应关系如下（右两列是 7.1 / 7.2 的落点）：

| L1 约定（对应 6.2 字段） | 机械判据 | 检出层 | 不过时 |
| --- | --- | --- | --- |
| `grade` 必填且 ∈ {A, B, C} | 缺失 / 越域（含小写、`"a "` 之类脏值） | L3.2 `grade_enum` | 返工；2 次仍不过 → 丢弃该条 |
| `statute_ids` 必填（A/B 级） | 空列表 / 非列表 | L3.2 `field_missing` | 返工 |
| `quote_statute` 必填（A/B 级） | 缺失 → L3.2；非所引条文连续子串 → L3.1 第 3 道 | L3.2 / L3.1 | 缺失返工；抄错则清空引用并按第 3 道降级（降级不返工，见 4.5.5） |
| `evidence` 必填、10–100 字、可定位 | 长度越界 → L3.2；定位失败 → L3.1 第 2 道 | L3.2 / L3.1 | 长度返工；定位失败属不可修正 → 直接丢弃 |
| `reason` 必填、≤ 200 字 | 空串 / 超长 | L3.2 `field_missing` / `length` | 返工 |
| `need_facts` ≤ 5 条、每条 ≤ 80 字 | 条数 / 单条字数 | L3.2 `length` | 返工 |
| `idx` 必填、整数且落在本批候选范围内 | 类型（`bool` 不算 `int`，`:393` 已有防御）/ 越界 | L3.2 `idx_out_of_range` | 返工（重指正确的 `idx`） |

一句话区分：**L1 是"要求"，L3.2 是"检查要求有没有被遵守"，L4 是"没遵守就退回去改"**。三者不是三套规则，而是同一条约定在三个位置上的形态。

## 7. 校验层：L3.1 六道核验加严 + L3.2 行为校验

模型成为主线后，六道核验不是"保留"，而是**每一道都要加一级强度**。本章分两节：7.1 是既有的六道（**全部属 L3.1**，六条与加严细节不变）；7.2 是新增的 L3.2 行为校验（判"模型守不守 L1"）。

### 7.1 L3.1 确定性校验：六道核验加严

| # | 现实现（`services/clause_review.py`） | 加严后 | 不过时处置 |
| --- | --- | --- | --- |
| 1 等级合法 | `_verify:306-309` 只接受 A/B/C，否则丢弃 | A 级必须同时具备 `statute_ids`、`evidence`、`quote_statute` 三件套；缺一件就**降为 B**（不再直接丢弃），B 缺依据降 C | 逐级降，不丢整批 |
| 2 证据可定位 | `_locate:84-100` 定位不到即丢；同段优先、否则退首次出现 | 增加长度硬校验（10–100 字，越界丢弃）；证据必须落在**候选所在段落内**（不再允许跨段回退到首次出现）；证据若跨段拼接（含换行）直接丢弃。**上限由 80 放宽到 100 的实测依据**：`contract_traps_01` 被触发器命中的段 20 整行 = 84 字、段 32 = 81 字，模型整行照抄是常见行为，上限 80 会把这两处典型对抗条款判成"长度越界"误杀；101 字仍拦截（P2-2 实测，见 `tests/test_clause_review.py` 的 84 / 100 / 101 三条用例） | 丢弃该条并记诊断 |
| 3 法条在库 | `:321-324` 条号须存在于 143 条库 | 在条号校验之上，加 `quote_statute` 必须是该条 `text` 归一化后的**连续子串**；条号伪造与原文仿写都被拦住 | 校验失败则清空该条引用；若因此 A/B 无依据，降 C |
| 4 引用闭集 | `:326-330` 触发器条目引用须在 `candidate_statute_ids` 内 | 闭集扩展为"候选闭集 ∪ 与本候选相关的规则 `statute_id`"（规则校验允许把数值依据引入，但闭集由程序算，模型仍不得自由引法） | 越界引用丢弃该条引用，其余保留 |
| 5 缺依据降级 | `:333-335` A/B 无法条降 C | 加两条：① A 级若 `need_facts` 非空 → 强制降 B（A 的定义是"无需补充事实"）；② B 级若 `need_facts` 为空且 `reason` 命中模糊词表（"可能""或许""大概""建议关注"）→ 降 C | 降级并记诊断，不丢弃 |

附加约束（不算新增道，挂在第 1、4 道上）：

- 自提 `extra` 仍按整份合同封顶 `max_extra = 3`（`review_clauses:423`），且必须过同样六道；与规则 `mismatch` 指向同一句时，以规则校验条为准，自提条目不重复报。

### 7.2 L3.2 行为校验（模型守不守 L1）

**它不判对错**：一条输出可能字段齐全但引错法条，那归 L3.1（第 3、4 道）。L3.2 只判"模型有没有按 6.2 的约定把字段交出来、交得对不对类型、在不在长度上限内"。

三条口径：

1. **诊断文案可区分**：L3.2 一律以 `L3.2 形态校验未过` 开头；L3.1 沿用现有 `{trigger_id}：...` 句式（如 `TR-PROBATION-TERM-EXCEED：引用越出候选闭集 LCL-99，已丢弃`）。V17 用 `Select-String -Pattern "L3.2 形态校验未过"` 与 `-Pattern "引用越出候选闭集"` 断言两者分得开。

3. **守 L1 = 过 L3.2**：L3.2 通过后若 L3.1 仍失败（如条号在库但越出闭集），那是"形态守了、依据错了"，按 4.5.2 第 3 类返工，与 L3.2 无关。

### 11.2 指标定义（沿用 `eval_clauses.py:18-24` 口径，明确分母）

| 指标 | 定义 | 分母 | 方向 |
| --- | --- | --- | --- |
| 覆盖率（召回） | 结论 span 与 gold span 重叠 ≥50% 的正样本条数 ÷ 该合同正样本数 | 正样本条数（38） | 越高越好 |
| A 级误报 | 该合同负样本里被判 A 的条数 | 负样本条数（57） | 越低越好（目标 0） |
| 引用准确率 | 结论引用落在对应 gold `statute_ids` 内的比例 | 引用总条数 | 越高越好 |
| span 定位率 | 结论 span 能在合同原文（`_norm` 后）定位的比例 | 结论条数 | 越高越好 |
| 分级一致率 | 与 gold `grade` 完全一致 ÷ 覆盖条数；另给相邻容忍口径（完全一致 1.0 + A↔B 相邻 0.5） | 覆盖条数 | 越高越好 |
| 稳定率 | 多次重跑等级不变的比例（现有 `run_consistency`） | 覆盖条数 | 越高越好 |

口径说明：以上指标的 `grade` 一律按**内部 A/B/C**（`clause_gold` 的标注即内部口径）；3.4 的对外两层只影响展示与排序，**不改变任何指标计算**。新增一条不进入主指标的展示层检查：影响度与确定性两层的排序是否正确（V18）。

置信区间（统一报 Wilson 95%，z = 1.96）：

```
p̂ = k / n
center = (p̂ + z²/(2n)) / (1 + z²/n)
half   = z * sqrt(p̂(1-p̂)/n + z²/(4n²)) / (1 + z²/n)
CI = [center - half, center + half]
```

### 11.3 开发集声明（必须写进报告与文档）

- 95 条由**单人标注**，只覆盖 **4 份合同**。
- 触发器对回归集覆盖 38/38 属**构造性覆盖**：gold 从 33 条增到 95 条的同时触发器从 21 条增到 28 条（evaluation.md:44-46），因此不能当作对未见合同的表现。
- 结论口径：这是**开发集**，只作内部回归与消融对照；对外只报"开发集 95 条上的 X（CI 下界 Y）"，不写"召回率 Z%"。
- 反对目标值：**禁止把 `rules_only` 的 1.0000 写进任何能力表**。

### 11.4 门槛（X 怎么定）

X 不在本规格预填。P3 第一步先冻结基线：对 4 份合同各跑 `eval_clauses.py --runs 1` 的 `full` 臂，把五个指标与分母条数写入 `data/evalsets/last_clause_eval.json`（现有落盘路径），该轮结果即基线 X；后续任何 P4/P5 改动，覆盖率与引用准确率**不得低于 X**，A 级误报**不得高于 X**（基线为 0 时保持 0）。
