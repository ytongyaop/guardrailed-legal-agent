# 杀软误报说明

## 为什么会被拦

本程序由 PyInstaller 打包，被杀毒软件误报是这类程序的常见情况，主要有三个原因：

- **没有数字签名**：本项目是个人开源项目，没有购买代码签名证书，exe 看不到受信任的发布者，Windows SmartScreen 也可能提示“未知发布者”。
- **新文件没有信誉**：杀软按文件传播量和存在时间评分，刚发布的版本天然是“新文件”，信誉分偏低。
- **打包形态触发启发式规则**：程序会把 Python 运行时和依赖库释放到磁盘，单文件打包每次启动还要自解压到临时目录，行为与某些恶意软件相似。

误报不等于真的有毒，但也不能只凭这句话让你放心，下面给出可自行核实的办法。

## 本项目的缓解措施

打包配置（`mla.spec`）已做四件事降低误报概率：

- 采用 onedir 目录模式而非单文件模式，启动时不向临时目录自解压。
- 不使用 UPX 压缩（`upx=False`），UPX 压缩过的可执行文件是误报重灾区。
- 嵌入完整的 Windows 版本信息：产品名、公司名、版本号写在 exe 的“属性 → 详细信息”里。
- 以 zip 压缩包分发整个程序目录，而不是直接散发单个 exe。

## 怎么验证文件没被篡改

在 zip 文件所在文件夹打开 PowerShell，运行（以 1.0.0 版为例，以后每个版本号以此类推）：

```powershell
Get-FileHash -Algorithm SHA256 .\mla-1.0.0-windows-x64.zip
```

把输出值与同一 Release 页面提供的 `mla-1.0.0-windows-x64.zip.sha256` 文件中的校验值逐字对比，完全一致才说明下载过程中文件未被改动。解压后也可以对 `mla\mla.exe` 再算一次。

## 被拦了怎么办

确认下载自项目官方 Release 页面、且哈希一致后，可按所用软件处理：

- **Windows Defender**：在“病毒和威胁防护 → 保护历史记录”中还原被拦文件，或在“排除项”里把解压后的 `mla` 文件夹加入排除列表。
- **360 安全卫士**：在“恢复区”还原，并在“信任与阻止”中加入信任。
- **火绒安全**：在“隔离区”恢复，并把 `mla` 文件夹加入信任区。

核心操作都是“先从隔离区还原，再把程序文件夹加入信任列表”。对来源不明或哈希对不上的文件，不要这样操作。

## 关于误报申诉

本项目会在每个发布版本发布后向 360、火绒等安全厂商提交误报申诉。审核需要时间，新版本初期仍可能被拦，信誉随文件传播逐步积累，过白名单后会好转。

## 如果你不放心

可以不下载任何二进制产物，直接审阅源码后自行构建。构建脚本已随仓库公开：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_packenv.ps1
powershell -ExecutionPolicy Bypass -File scripts\build_exe.ps1
```

需要本机安装 uv（用于创建 Python 3.12 构建环境）与 Node 20 以上版本；Python 解释器由 uv 自动准备，不必预先安装。产物在 `dist\mla\mla.exe`。自行构建的文件同样没有数字签名，但内容完全由你机器上的源码决定。
