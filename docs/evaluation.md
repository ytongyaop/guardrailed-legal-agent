# 评测设计与结果

本文说明四套评测集的构造方式、指标定义、当前结果与全部已知局限。

## 评测什么

每个能力层都有对应的评测载体，哪个数字度量哪一层一目了然：

| 能力 | 由谁度量 | 对应指标 |
| --- | --- | --- |
| 数值域规则判定 | 主评测集、泛化集（标注为应命中的规则 ID） | 准确率、召回率 |
| 追问机制 | 主评测集的事实缺失与事实齐全用例 | 补问触发率、不误问率 |
| 越界拒答 | 主评测集的越界与界内边缘用例 | 越界拒答率、误拒率 |
| 依据可溯源 | 全部产出结论的用例 | 可追溯率、建议无依据率 |
| 问答与检索 | 问答集（标注应引法条） | 可答率、引用存在率、引用命中率 |
| 存在性域条款判定 | 条款 gold（38 条陷阱 ＋ 57 条合规条款） | 覆盖率、A 级误报、引用准确率 |
| 缺项域 | 无独立评测集，只有 4 份合同的逐类人工对照 | 必备条款覆盖率（人工基线） |

## 评测集构造

### 主评测集（52 条，`data/evalsets/eval_cases.jsonl`）

每条用例带合同片段或结构化事实，标注应命中的规则 ID（`gold_items`）与是否应触发补问（`expect_ask`）。用例覆盖违规命中、事实缺失、事实齐全、越界提问、界内边缘提问等类别：第一类测判定准确，后几类分别测补问触发、不误问、拒答与不误拒。正样本合同取自官方示范文本；负样本在示范文本上人工植入违法或缺失条款，gold 由脚本按植入清单自动生成、人工只做抽样复核，植入清单另行保存、不随评测集公布。

### 泛化集（12 条，`data/evalsets/eval_generalization.jsonl`）

非模板合同，检验脱离模板句式后抽取与判定是否仍然成立。条款级评测对这 12 条只做噪音检查（报候选数、结论数与等级分布，供人工判断有无明显离谱结论），不算准确率、不造 gold。

### 问答集（20 条，`data/evalsets/qa_cases.jsonl`）

每条一个自然语言问题，附人工标注的应引法条 ID。评测脚本按消融臂运行：模型单跑、加 BM25、加向量、加 RRF 融合，度量可答率、引用存在率（引用条号都在法源库内）、引用命中率（引用里至少有一条是标注的应引法条）、工具轮数与平均耗时。模型单跑臂是对照，用来检验没有检索时引用是否可靠。

### 条款 gold（95 条，`data/evalsets/clause_gold.jsonl`）

基于 4 份合同：3 份对抗合同植入 38 条陷阱（正样本），1 份全合规对照含 57 条合规条款（负样本）。逐条标注应判等级与应引法条，用于存在性域的覆盖率、误报与引用评测。

## 指标定义

主流程指标（`scripts/run_eval.py`；准确率为命中条数除以系统输出条数、召回率为命中条数除以标注条数，跨全部用例微平均，另逐条计算 Jaccard 作参考）：

| 指标 | 定义 | 方向 |
| --- | --- | --- |
| 准确率 | 命中标注的条目 ÷ 系统输出的条目 | 越高越好 |
| 召回率 | 命中标注的条目 ÷ 标注的条目 | 越高越好 |
| 可追溯率 | `source_id` 落在允许依据集合（规则表法条与规则 ID ＋ 本轮检索命中）内的结论占比 | 校验器强制 100%，是放行条件 |
| 补问触发率 | 事实缺失用例中发生了补问的比例 | 越高越好 |
| 不误问率 | 事实齐全用例中没有发生补问的比例 | 越高越好 |
| 越界拒答率 | 越界问题被拒答的比例 | 越高越好 |
| 误拒率 | 界内问题被拒答、或没给出带依据回答的比例（空回答同样计为失败） | 越低越好 |

建议类条目另有硬约束：无依据率上限为 0——没有依据的建议直接拒绝生成，不进入输出。

条款级指标（`scripts/eval_clauses.py`，逐合同独立计算后汇总）：

| 指标 | 定义 |
| --- | --- |
| 覆盖率 | 正样本陷阱被结论覆盖的比例；结论片段与标注片段重叠不低于 50% 记为命中 |
| A 级误报 | 负样本合规条款被判为 A 级的条数 |
| 引用准确率 | 结论引用的法条落在标注法条集合内的比例；库外条号单列统计 |

脚本同时输出 span 定位率与分级一致率，本文只引用上表三项。主流程评测另有按 `--variant` 拆层的消融臂（`rules_only` / `rules_retrieval` / `llm_only` / `full`，默认 `all` 连跑 rules_only、rules_retrieval、full 三臂），条款级另设关闭程序核验的模型裸输出臂，用于度量各层的独立贡献；消融结果不作为对外指标。未启用生成层的消融臂（`rules_only`、`rules_retrieval`）不产出问答类指标，`false_refuse` 记为无值；越界拒答率在各臂均可测。

## 结果

主流程（抽取档通过 `--extract` 单独度量）：

| 评测集 | 抽取档 | 准确率 | 召回率 |
| --- | --- | --- | --- |
| 主评测集（52 条） | 纯正则 | 1.0000 | 1.0000 |
| 主评测集（52 条） | 接入模型 | 1.0000 | 1.0000 |
| 泛化集（12 条非模板合同） | 纯正则 | 0.4167 | 0.3636 |
| 泛化集（12 条非模板合同） | 接入模型 | 1.0000 | 1.0000 |

口径：纯正则抽取只能为 20 条规则中的 7 条提供全部依赖字段，在随库分发的 52 条评测合同上实际触发违规判定的规则为 4 条，接入模型抽取后 20 条全部可判。主集文本是模板化写法，满分是"模板文本 ＋ 相应抽取档"的组合结果；泛化集的正则档数字才反映正则抽取在自然写法下的真实水平。

条款级（3 份对抗合同 ＋ 1 份全合规对照）：

| 项 | 结果 |
| --- | --- |
| 陷阱命中 | 38 条全部命中 |
| A 级误报 | 57 条合规条款中为 0 |
| 引用准确率 | 多轮运行在 0.92 至 0.95 之间波动（模型非确定性，见局限） |

必备条款覆盖率（同 4 份合同，逐类人工对照）：1.000 / 1.000 / 0.875 / 0.750。口径：覆盖率分母不含第（九）类兜底规格；该层没有独立评测集，这组数字是人工对照基线，不是自动评测输出。

## 局限

1. 开发集问题：四套评测集全部由开发者自己构造，写规则的人和出题的人是同一批，没有外部盲测集。系统对"自己出的题"表现好，不等于对真实合同表现好。
2. 单人标注：gold 由植入清单自动生成加人工抽样复核，复核也只有一个人，没有第二标注者交叉验证，标注偏差无法估计。
3. 抽取档是最大变量：纯正则抽取只能为 20 条规则中的 7 条提供全部依赖字段，在随库分发的 52 条评测合同上实际触发违规判定的规则为 4 条，接入模型抽取后 20 条全部可判。离开模板写法，正则档在泛化集上只有 0.4167 / 0.3636。
4. 条款级样本太少：只有 4 份合同、95 条 gold。陷阱是人工植入的，比真实合同里的风险更集中、更显眼；28 条触发器在真实合同多样性下的组合表现没有被度量。
5. 缺项域没有独立 gold：只有 4 份合同的逐类人工对照基线。逐行匹配对同义表述、排版变体的漏检风险没有被量化。
6. 模型非确定性：引用准确率在多轮运行间于 0.92 至 0.95 波动。程序核验能拦住库外条号和越出候选闭集的引用，但"闭集内引错条"无法被核验完全消除，只能靠候选闭集本身的质量约束。
7. 口径声明：本文所有指标不能当作泛化结论引用；对外表述时必须连同评测集规模、构造方式与本节局限一起给出。

## 复现

| 命令 | 内容 |
| --- | --- |
| `pytest` | 337 条测试，强制纯正则抽取并屏蔽真实 Key，离线可复现 |
| `python scripts/run_eval.py --extract regex` | 主评测集，纯正则抽取档 |
| `python scripts/run_eval.py --extract llm` | 主评测集，模型抽取档（需配置 `MLA_LLM_API_KEY`） |
| `python scripts/run_eval.py --variant rules_only` | 消融臂示例：只跑确定性规则，不接模型 |
| `python scripts/run_eval.py --cases data/evalsets/eval_generalization.jsonl` | 泛化集 |
| `python scripts/run_eval.py --check-determinism` | 校验相同输入下结果的确定性 |
| `python scripts/eval_clauses.py --runs 1` | 条款级评测单轮；加大 `--runs` 可观察等级稳定率 |
| `python scripts/eval_qa.py` | 问答检索消融；模型与向量臂需配置 Key，BM25 臂可离线 |
